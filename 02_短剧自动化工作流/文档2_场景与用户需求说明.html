一页速读

短剧团队要的是「一份剧本 → 一集能进剪辑的成片」，中间最痛的是角色换脸、镜头跑偏、批量跑到一半崩掉。MVP 做一条被裁剪过的端侧产线：本地小模型拆分镜 → 角色锚图库钉住身份 → 快速出关键帧 → 只对审片通过的镜头做 5 秒内图生视频 → 审片台逐镜头打回 → 按镜头断点续跑 → 本地拼接导出。不承诺实时预览、不承诺长镜头 1080p、不承诺无限并发——把这些边界写清楚，这个场景才真的适合端侧。

01场景与用户需求

用户画像

短剧工作室 / 小团队
一周要出多集，编导、美术、剪辑往往一人兼；最缺的是把脚本快速变成可视画面的能力。
MCN 内容团队
同一 IP 角色要长期连载，形象一旦漂移，粉丝立刻看出来；未发布剧本和艺人形象保密。
独立创作者
没有 GPU 集群，只有一台创作主机；能接受「晚上挂着跑、早上来收货」，但不能接受中途崩了全重来。

Jobs-to-be-Done

用户说法真实需求当前痛点
「这段剧本拆成镜头」结构化分镜表：景别、人物、动作、时长、提示词手工拆镜 + 手写提示词，慢且不一致
「主角每一集都得是同一张脸」跨镜头、跨集的身份一致性通用生成逐镜漂移，越到后面越不像
「先给我看看大概效果」低成本快速预演，别一上来就跑终稿视频生成几分钟一次，试错代价极高
「这 3 个镜头不行，重做」只重跑打回的镜头，别整集重来整批重跑，几小时白费
「剧本不能外传」脚本、角色形象、成片全程本地云端视频工具的合规顾虑
为什么这个场景（在裁剪之后）适合端侧① 保密刚需：未发布剧本、角色设定、艺人形象属于核心资产，本地推理天然不出内网。
② 批量可离线：成片不是实时需求，天然适合夜间后台排队，正好用满单机算力。
③ 成本结构：连载型高频产出能摊薄硬件成本；偶发任务反而云端更划算。
④ 可复现：分镜脚本、锚图、seed、模型版本本地存档，客户要「再出一版」可重放。
⑤ 但必须承认边界：短视频镜头（≤5s、竖屏 480/720p、I2V 为主）端侧能稳定交货；长镜头、高分辨率、实时预览不能。把场景定义到这个边界内，才是「选择适合端侧的场景」的真实含义——不是硬套一个云端场景，而是按端侧能力重新划定交付范围。

02MVP 范围

MVP 做
① 剧本 → 结构化分镜表（本地小模型）
② 角色锚图库与一致性控制
③ 关键帧 / 分镜图快速生成
④ 5 秒内 I2V 短镜头渲染 + 分段 checkpoint
⑤ 审片台（通过 / 打回 / 批注）
⑥ 只重跑打回镜头的批量编排
⑦ 本地拼接与导出
⑧ 脚本版本 / 锚图 / 草稿全量落盘
MVP 明确不做
× 1080p / 4K、长镜头、实时预览
× 纯文生视频长片（改走关键帧 + I2V）
× 配音、口型、BGM 自动生成（预留占位即可）
× 多人云协作 / 云端渲染
× 同时渲染多个镜头（单卡物理上限）
× 自动联网补模型
范围判断MVP 只保留「从一份剧本到一集可进剪辑的成片」这条闭环。配音/口型虽然诱人，但去掉它链条依然能交货，所以后置。

03核心模块拆解与协作

#模块解决什么问题输入 → 输出依赖 / 下游
M1剧本 / 分镜解析器把非结构化剧本变成机器可执行的分镜表，用户不用手写提示词剧本文本 → 结构化 JSON（镜头号、景别、人物、动作、时长、正/负提示词）为 M3/M4 提供任务清单；脚本本身版本化
M2角色资产库身份的唯一真相源：3–5 张多视角锚图、角色 LoRA、触发词、服装设定角色设定 → 角色卡（含锚图哈希与版本号）M3 每次生成都 re-anchor 到这里
M3一致性引擎跨镜头不换脸、不变服装；姿态与景别可控角色卡 + 分镜描述 → 带参考图 / LoRA / OpenPose 约束的工作流参数供 M4 出关键帧；禁止把上一镜头输出当参考
M4关键帧生成以秒级成本把画面定稿，避免昂贵的视频试错分镜 + 约束参数 → 关键帧候选图交 M6 审片；通过后才有资格进 M5
M5短镜头渲染把关键帧变成 5 秒内视频；按帧段存 checkpoint已通过的关键帧 → 分段视频帧 + 镜头成片向 M7 汇报帧段进度；失败只重跑失败帧段
M6审片台逐镜头通过 / 打回 / 批注；把人的判断接回流水线关键帧 / 成片 → 审片结论 + 打回任务打回任务插回队列，优先级高于批量
M7批量编排与出片镜头级队列、夜间批量、断点续跑、本地拼接导出分镜表 → 有序任务 + 最终成片调用本地推理 API；详见文档 ③
M8草稿与恢复中心横切：脚本版本、锚图、审片批注、队列状态全部落盘所有状态变更 → 本地快照被 M1–M7 共同调用

04端到端工作流（对应 Demo 里能点的每一步）

粘贴剧本→解析分镜表→建角色卡 / 锚图→批量出关键帧→审片通过或打回→I2V 短镜头→分段续跑→拼接导出
步骤用户动作系统动作状态落盘
1粘贴剧本 / 导入文本本地 Qwen3-4B 解析成分镜 JSON，用户可逐条改脚本版本 + 分镜表
2上传 3–5 张角色参考图生成角色卡、锚图哈希、触发词；可训练/挂载 LoRA角色卡版本 + 锚图
3点「生成关键帧」批量排队，每镜头 re-anchor，秒级出候选参数 + seed + 候选图
4在审片台通过 / 打回打回镜头生成高优先级增量任务；通过的进入视频队列审片结论 + 批注
5选择预演档或终稿档逐镜头渲染，按帧段写 checkpoint，实时显示进度帧段 checkpoint + 进度
6中途中断 / 模拟失败只影响当前镜头；已完成帧段与其他镜头不受影响中断点 + 恢复点
7一键续跑 + 导出从最后 checkpoint 续跑，本地拼接、导出成片与复现包成片 + 复现参数包

05关键页面与交互说明（Demo 的对应关系）

页面区域关键交互要体现的产品决策
上：剧本 / 分镜表粘贴剧本 → 一键解析；逐行编辑景别、动作、时长结构化输出是本地小模型的价值，不是聊天
左：角色卡锚图缩略图、re-anchor 开关、漂移告警锚图是唯一真相源；关掉开关会提示漂移风险
中：镜头卡片墙每个镜头显示关键帧 / 视频状态与帧段进度镜头级状态可见；长任务要给逐帧进度
右：审片面板通过 / 打回 / 批注，打回自动插队把人的判断接回流水线，只重跑该重跑的
底：批量队列预演档 / 终稿档、暂停、中断本镜头、模拟失败、续跑分段 checkpoint 与按镜头恢复
全局：自动存稿灯刷新后脚本、锚图、批注、队列仍在三层持久化 + 版本化

06MVP 验收标准

验收项标准
闭环完整一份剧本 → 一集可进剪辑的成片，全程零联网
角色一致性跨 10 镜头盲测「同一人」均值 ≥ 4.0，严重换脸 = 0
失败隔离单镜头 OOM / 中断不影响其他镜头，已完成帧段不丢
恢复强制结束进程后重启，脚本、锚图、批注、队列 100% 还原，并从 checkpoint 续跑
可复现任一镜头可用存档的分镜 + 锚图 + seed + 模型版本重出
边界清晰界面明确标注 5s / 480–720p / 非实时，不承诺端侧做不到的事

08老师可能追问什么

「为什么不用最强的 FLUX.2？」
两个硬理由：社区许可非商用（电商/短剧都是要交货的），且 32B 模型 33.8GB 超出 24GB 显存，offload 后单张要几分钟，端侧批量不现实。
「没有云端兜底，慢了怎么办？」
答降级阶梯：降分辨率 → 减步数 → 卸载大模型 → 暂停后台保前台 → 明确拒绝并提示。绝不静默失败，也绝不偷调云 API。
「主观效果怎么算评估？」
答盲测 + 5 分制评分表 + 多人取均值 + 锚图 A/B + 固定 seed 可复现。主观维度也要可操作、可复议。
「并发不就是把任务排队吗？」
答四层：状态机、优先级与配额、按错误类型分类恢复、三层持久化（草稿 / 参数 / 产物）。排队只是第一层。
