这份指南解决什么：你的 Dify 是云端版（cloud.dify.ai），和作业里假设的「自部署在本机」不是一回事。云端版有两件事做不到：①它的 HTTP 节点访问不到你 Mac 上的 127.0.0.1；②它没有本地模型可选。所以云端版做的是「同样的编排逻辑，用云端模型跑通给你看」——学 Dify 搭建、看结构化输出效果，都用它。

00 · 30 秒版

  1. 在 Dify 里导入 05_Dify云端版/Dify云端_电商素材工作流.yml（导入方法见 02 节）。
  2. 打开 LLM 节点，把模型换成你账号里可用的任意一个（03 节，10 秒）。
  3. 点右上角运行试跑 → 能出 plan_json 就算搭建成功。之后要接出图服务再看 04 节，要发 API Key 给助手再看 05 节。

01 · 你给的链接怎么用

你给的 cloud.dify.ai/app/16dbd924-.../workflow 是一个已创建好的空白工作流应用。DSL 导入有两种走法：

走法怎么操作适合谁
A. 导入 DSL（推荐）回到 Dify 工作室首页 →「创建应用」→「导入 DSL 文件」→ 上传本目录的 yml → 会生成一个新应用（你原来的空白应用可以删掉）所有人。5 个节点 4 条连线一次到位
B. 在现有应用里手动搭打开你链接里的应用，照 02 节的节点表自己拖：开始 → LLM → 代码 → HTTP → 结束想练手 Dify 的人，约 15 分钟
注意：Dify 的「导入 DSL」一般会新建应用，不是覆盖你打开的那个。导入成功后，从工作室首页点进新出现的那张卡片就是。

02 · 导入步骤（逐张点）

  1. 下载/找到文件：05_Dify云端版/Dify云端_电商素材工作流.yml（电商版）和 Dify云端_短剧自动化工作流.yml（短剧版），两个可都导。
  2. 浏览器打开 cloud.dify.ai，左侧点「工作室」。
  3. 点左上角「创建空白应用」按钮旁的箭头 → 选「导入 DSL 文件」（部分版本在「创建应用」弹窗里）。
  4. 上传 yml 文件 → 点「创建文件」。如果提示版本不兼容，选「仍要导入」即可。
  5. 导入后进画布，应看到 5 个节点：开始 → LLM 拆解 → 代码校验 → HTTP 提交 → 结束。LLM 节点上可能有红色感叹号——正常，去 03 节选模型就消了。
  6. 点右上角「运行」，在右侧填几个参数（商品名称随便写，如「保温杯」），看运行结果里的 plan 输出。

导入后的节点与作用（和本地版完全同构）：

节点做什么云端版要注意什么
开始 · 批量参数商品名、风格、尺寸、SKU 数、候选数不用改
LLM · 需求拆解把需求拆成结构化 JSON 任务清单必须换成你的模型（见 03）
代码 · 校验与展开去围栏、解析 JSON、补字段、数量校验不用改（Dify 云端代码沙箱支持 python3）
HTTP · 提交出图调 {{#env.API_BASE#}}/api/ecom/generate地址走环境变量（见 04）
结束 · 回传画布输出 plan / generate_result / summary不用改

03 · 模型怎么选（10 秒的事）

  1. 画布上点开 LLM 节点。
  2. 右侧面板顶部「模型」下拉，选一个你账号里有额度的：DeepSeek / 通义千问 / GPT-4o-mini / GLM 等都可以。提示词已写死，换任何模型都不用改提示词。
  3. 温度已设 0.2、max_tokens 1400，不用动。
为什么哪个模型都行：这套工作流的可靠性不押在模型上——提示词约束 + 代码节点兜底校验双保险，这正是作业里「结构化输出」设计点的演示。小模型吐错 JSON，代码节点会本地兜底重建任务清单，绝不重试、不转云端。

04 · 服务地址怎么填（API_BASE）

云端 Dify 够不到你 Mac 上的 127.0.0.1:8765（那是「你自己家」的地址，云端在别人家）。要让 HTTP 节点真正调到出图编排服务，三条路：

方案做法成本推荐度
① 先不接，只跑前半段什么都不填。运行到 HTTP 节点会失败，但 plan_json 已经出来——搭 Dify 的目的已达成零现在就能用
② ngrok 内网穿透本机跑 python3 local_api_server.py --host 0.0.0.0，再开 ngrok 隧道，把 https 地址填进环境变量免费版够用，但地址每次重启会变想看全链路时用
③ 部署到公网小主机把 local_api_server.py + engine_drivers.py 丢到 Render / Railway 等免费层免费层会休眠，首次慢长期演示用

填法：工作流画布右上角点「环境变量」图标 → 编辑 API_BASE → 把默认值换成你的地址（不带末尾斜杠）。改这一处，HTTP 节点自动跟着变。

05 · 发布并拿 API Key（发给我那一步）

  1. 画布右上角点「发布」（先运行成功一次再发布）。
  2. 左侧菜单「访问 API」（部分版本在「API 访问」）。
  3. 页面右上角「API 密钥」按钮 → 「创建密钥」 → 复制 app- 开头那串。
  4. 把它发给助手（就是你说的「API 后续补给你」），并注明是哪个应用的（电商 / 短剧）。
拿到密钥后，助手可以直接替你调 POST https://api.dify.ai/v1/workflows/run 实测你的工作流、修问题、把返回结构对接进 Demo。

06 · 红线口径：云端版 ≠ 作业方案

作业的硬约束是「全部推理在本地，无云端兜底」。云端版 Dify 里跑的 LLM 是云端模型——所以它不能写进作业正文，只能作为「我在 Dify 上验证过编排逻辑」的佐证。
