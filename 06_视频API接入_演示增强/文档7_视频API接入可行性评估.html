文档 7 · 演示增强通道（不进作业正文）

接入生成视频网站的 API —— 可行性评估红线隔离

一句话结论：技术上完全能接，而且这些 API 的异步形态和本作业里已经画好的「队列状态机 / 显式降级」几乎一模一样；但它会破掉题干「全部推理在本地、无云端兜底」这条核心约束，所以只能作为独立标注的演示增强，不能混进交付主体。

01三条必须先讲清的红线

红线一 · 约束冲突（最重要） 作业题干要求端侧推理、无云端兜底。视频生成 API 的全部算力都在厂商机房，属于典型的云端兜底。若把它写进正式方案，等于自己推翻了 Part1 的模型选型与评估结论。正确做法：单独开一个「演示增强」目录，明确标注不进正文，答辩时作为「如果放开约束，架构怎么扩展」的加分回答。
红线二 · 接口形态完全不同（异步，不是同步） 生产级视频 API 几乎全是 提交任务 → 拿 task_id → 轮询 的两段式，单片段通常 1~5 分钟。而 Dify 云端工作流整体超时默认约 200 秒、HTTP 节点建议 30 秒，直接把视频 API 塞进现有那个 HTTP 节点会必然超时。必须加一层「异步转同步」的适配器，或者改成提交后交给队列状态机。
红线三 · 需要资质与钱 国内主流平台基本都要实名认证、充值，按秒计费约 0.25~0.9 元/秒；免费额度多半是网页端积分，不等于 API 免费额度。作业演示建议只用免费 API 或明确的降级模式，避免现场翻车。
好消息 这些约束带来的「异步任务 / 状态机 / 失败重试 / 超时后保留 task_id / 显式降级」，恰好就是文档3《多任务并发与不丢稿》里已经设计好的东西。接视频 API 不需要改架构，只需要换一个驱动 —— 这点在答辩里非常值钱。

02标准接入形态：三段式异步链路

下图是各家视频 API 的通用形态（硅基流动 /video/submit + /video/status、阿里百炼 X-DashScope-Async、可灵、即梦、MiniMax 都是这个套路）。

一个容易踩的坑 本地轮询超时 不等于任务失败。必须把 requestId 持久化下来让别的 worker 续查；绝对不要重新提交一次，否则会生成两段视频、重复扣费。这正是文档3「不丢稿」要解决的问题。

04三条可选路线（按推荐度排序）

A · 保持现状（推荐交作业）
分镜 JSON + 关键帧 + 交互 Demo，视频任务转待办。端侧约束 100% 成立，答辩口径已在文档5 写好。代价：现场看不到「动起来」。
B · 关键帧拼预演 MP4
把已生成的关键帧按顺序加转场拼成镜头预览，明确标注「分镜预演稿，非模型生成」。零成本、零约束冲突，几分钟就能做，现场效果最好。
C · 真接视频 API（演示增强）
用本目录的适配器接免费/低价视频 API，产出真 MP4。必须单独标注不进正文，且要准备回答「这算不算云端兜底」。
如果选 C，请务必这样讲 「正式方案仍是纯端侧。这一段是对照实验：用来验证当算力约束放开后，我设计的队列状态机和降级策略能否原样复用，结论是可以——只换了驱动，没改架构。」把主动权拿回来，而不是被问出「你违反了自己的约束」。

05选 C 的话，具体改这三处

① 适配器已经写好：video_api_adapter.py

零依赖（只用 Python 标准库），把「提交 + 轮询 + 取 URL」封装成一个普通 HTTP 接口。默认不配 key 就显式降级并返回原因，绝不假装成功 —— 这条跟作业里的降级设计完全一致。

# 零成本看形态，不发任何外部请求
python3 video_api_adapter.py --mock --prompt "柯基叼着棉花糖飘过天台"

# 真跑（模型名以平台控制台实际可用名为准）
export VIDEO_API_KEY=你的密钥
python3 video_api_adapter.py --provider siliconflow \
  --model "Wan-AI/Wan2.2-T2V-A14B" --prompt "柯基叼着棉花糖飘过天台"

# 起服务，让 Dify / 本地编排服务调用
python3 video_api_adapter.py --serve 8766
# POST http://127.0.0.1:8766/api/video/generate  {"prompt":"...","wait":true}

② 接进现有编排（改动很小）

位置改法

③ 换平台只需改一张表

适配器顶部的 PROVIDERS 字典登记了端点、鉴权方式、任务 ID 与状态字段名。可灵 / 即梦 / 阿里百炼加一条配置即可，主流程不用重写。这也是文档1 里「模型可替换性」评估维度的一个现成证据。

07答辩问答（背这两句就够）

Q：为什么没接视频 API？端侧不是也能调外部服务吗？ 「不能。题干明确无云端兜底，视频 API 的算力全在厂商机房，接了就等于推翻 Part1 的选型结论。我的处理是把它显式降级为分镜故事板 + 关键帧，视频任务转待办，交付不中断、不静默失败。」
Q：如果给你 24GB 显存 / 放开约束，架构要不要重写？ 「不用重写。视频生成天然是异步任务，而我文档3 的队列状态机、失败恢复、不丢稿已经按异步任务设计好了。接 API 只需在驱动层加一个 submit / poll 适配器，编排层、审片台、降级策略全部原样复用 —— 这也是我把推理层做成可替换驱动的原因。」
