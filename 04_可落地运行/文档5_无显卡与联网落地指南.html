01这台机器实测到了什么

项目实测值对方案的影响
机型 / 芯片MacBook Air · Apple M5 · 10 核 CPU / 8 核 GPU统一内存架构，不是独立显存
内存16 GB 统一内存（系统占用后可用约 10–12GB）文档①的 20GB 显存预算必须重算

一个容易混的点统一内存 ≠ 显存。GPU 和 CPU 抢同一块 16GB，所以「模型卡说 16GB 能跑」在这台机器上通常意味着会 swap、明显变慢，而不是流畅生产。

06生产落地（路线 D）：接上真正的端侧主机

这一层才对得上题目原设。上层（两个 Demo、两份 Dify DSL、API 契约、文档③的队列策略）一行都不用改，只换引擎驱动：

# 1) 在 ComfyUI 里搭好工作流，导出 workflow_api.json 放到 03_Dify工作流与API接入/
# 2) 启动本机 ComfyUI（默认 8188 端口）
# 3) 用本地引擎启动编排服务
python3 local_api_server.py --engine local

# 可选：ComfyUI 在别的机器上 / 换了端口
COMFYUI_BASE=http://192.168.1.20:8188 python3 local_api_server.py --engine local
COMFYUI_WORKFLOW_JSON=/path/to/my.json python3 local_api_server.py --engine local

# 如果 Dify 跑在 Docker 里，服务要监听 0.0.0.0
python3 local_api_server.py --engine local --host 0.0.0.0

驱动做的事是真实的 ComfyUI API 流程：注入正向提示词与 seed 到 workflow_api.json → POST /prompt → 轮询 /history/{prompt_id} → /view 取回图片 → 落盘。失败只报本地错误并降级，没有任何自动转云端的分支。

09老师可能追问什么

「没有显卡你怎么验证？」
分两层答：编排层不需要显卡，队列 / 中断 / 恢复 / 自动存稿都在本机真跑；像素层我用联网开发通道和 Apple Metal 小模型分别验证过，并说清各自的边界。
「24GB 显卡的假设从哪来？」
题目没给硬件，我在文档①开头把它写成显式假设，并做了 16GB Mac 的敏感性重算（第 03 节）——硬件变了，档位和指标要跟着变，选型逻辑不变。
「这不就是调用云端 API 吗？」
不是兜底，是显式切换的开发引擎；正式方案 cloud_fallback 恒为 false，失败只在本地降级。而且我已经把 --engine local 到 ComfyUI 的真实路径写好了。
「真机上要改多少？」
上层零改动：两个 Demo、两份 DSL、API 契约、文档③的队列策略全部复用，只替换引擎驱动一个函数。
